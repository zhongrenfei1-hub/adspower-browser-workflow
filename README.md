# AdsPower 浏览器会话配置与注册操作记录

修订日期 2026-11-27

本仓库保存人工辅助操作规程。目前没有可执行配置、自动化程序或已安装的 Codex 技能。

## 隔离范围与证据

每个新账号使用一个新 AdsPower 环境，分别保存 Cookie、缓存和登录会话。执行时还需验证 localStorage、IndexedDB、Service Worker 等站点存储没有被导入或同步。环境目录分开只能说明本地会话管理范围，网络出口、硬件、浏览器行为以及服务端账号记录仍可能相同。

本地直连环境共享当前网络出口。IP、时区和语言相同在同一网络下是正常现象。它们不能作为环境互相隔离的证据。具体平台如何加权 IP、时序或其他信号尚未验证。

同环境登录邮箱与目标服务，会在同一网络和浏览器上下文中发生访问。这一事实本身无法证明两个独立服务共享或绑定了彼此的会话数据。

## 配置前核对

1. 确认用途、目标服务、用户授权和已存在的环境，避免重复注册。
2. 若需要验证真实 macOS 行为，使用实际 macOS 设备。Windows 上选择 macOS 属于跨系统模拟，需记录为未验证的兼容性范围。
3. 优先使用当前受支持、已更新的内核。记录完整版本和补丁版本，并观察 UA、Client Hints 与实际浏览器行为。主版本对齐仅是一项检查。UA 的冻结值、字段缺省和浏览器隐私限制需按官方语义解释。
4. 字体、Canvas、WebGL、WebGPU、屏幕尺寸、DPR、hardwareConcurrency、deviceMemory 和 platform 应通过实际页面观测，记录缺失值和测试限制。界面中的真实值、默认值或噪音标签不足以证明真实输出及其跨系统一致性。
5. WebRTC 模式依赖所需功能和网络配置。先验证音视频功能及实际网络行为，再决定模式。禁止把禁用作为普遍更安全的结论。
6. TLS 与 HTTP/2 等行为需要受控的网络测试证据。无法观测时标记未验证，不能根据 UA 推断。
7. 保存前核对环境概要，启动后复核实际版本、站点存储与功能。

具体噪音开关、字体列表、硬件参数和 DPR 不设通用最优值。统一加噪或固定 DPR 为 2 同样需要验证。

## 本地状态与重试

每次操作在本地私有记录中维护以下字段，记录文件放在仓库工作目录之外。

- 不透明任务编号、环境 ID、环境名称、创建时间、更新时间。
- 主机系统、模拟系统选择、完整内核与补丁版本、UA 与 Client Hints 检查结果。
- 屏幕尺寸、DPR、硬件观测摘要、网络模式、已验证项目和未验证项目。
- 当前阶段、最后成功步骤、错误原文的脱敏摘要、下一步动作。

状态依次使用 planned、profile_created、browser_verified、email_pending、verification_pending、terms_pending、onboarding、ready。外部验证不可用时记录 awaiting_user，明确拒绝时记录 blocked，其他失败记录 failed。

重试前读取本地状态并核对页面。验证邮件未到时只按页面允许的方式重发，避免重复创建环境或重复提交注册。半成品保留环境与停点，完成后更新同一条记录。

账号密码、辅助邮箱、短信或验证器密钥、Cookie、邮件验证链接及原始网络日志不得进入公开仓库或提交历史。

## 注册与停止条件

1. 在对应环境访问服务官方入口，使用用户指定邮箱。
2. 使用用户授权的邮箱登录方式读取验证邮件，仅处理当前注册需要的邮件。
3. CAPTCHA 按工具要求取得当次确认。无法完成时保留页面与停点。
4. 手机、短信、验证器、设备确认不可访问时等待用户提供有效验证渠道。明确拒绝、地区限制或账号限制出现时记录原因并停止该路径。
5. 条款和年龄确认需要用户明确授权。更换密码或建立新凭据时按工具要求交由用户。
6. 免费或付费方案、显示名称、营销订阅和数据改进选项依据用户选择。一次操作中的选择不自动变成后续必选项。
7. 验证进入聊天页面及账号状态，记录环境 ID、完整版本和遗留问题。ready 只代表当前注册流程完成。环境隔离测试和长期账号状态分别记录。
